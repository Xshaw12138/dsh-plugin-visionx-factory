# 默认随方案交付的三维概念布局

用于工厂、产线、立库、RGV/AGV 与物流规划；不是 VisionX 实时操作说明。

## 从业务话语到布局

先确定设备/区域及入出物流关系，再安排空间、绘图和说明设计理由。
数量未知时可以提出候选配置，但必须写成建议。尺寸未知时使用标注清晰的
示意参数，不把它称为现场布置图、工程定案或已验证的最优方案。

布局交付在进入方案态后的首轮方案中完成，摘要后就能看见图。没有任何用户现场
事实时先执行需求采集态，只问一个聚合问题且不绘图；用户提供部分事实后直接交付
基于已有事实的受限示意方案，缺失尺寸保留待确认。除非用户只要文字，不要把
“需要的话我再画图”作为默认结尾。

## 图面要能回答的问题

- 设备和区域在哪里？立库、堆垛机通道、RGV 轨道、车体、交接输送机分别画出。
- 物料从哪里来、到哪里去？每条路线标识命名起点、顺序交接点、命名终点和方向；不能闭合的段落直接标为待确认缺口。
- 占多大位置？有尺寸时按同一比例投影并标关键尺寸；无尺寸写“示意，不按比例”。
- 为什么这样放？在图旁解释共享设备、路线、缓冲和现场约束，不只贴设备标签。
- 哪些还不能断言？用一处简短状态提示说明假设与仿真进度。

用等轴测投影展示高度与空间，用俯视图补充物流方向和通道。图多时保持同一编号。
两层及以上默认交付“整厂爆炸/剖切总览 + 每层独立俯视图”；跨层路线在每层都标出进/出的垂直转运点，并在总览中画出升降段。
不同楼层的设备和路线不压到同一张俯视图。默认只显示中文区域名、入口、出口、交接/换层点和当前主路线；设备内部 ID 放在悬停信息或附录。
图中主路径不得被高货架遮住；允许隐藏货架或切换俯视，但不能改变几何来美化图。
静态轴测图应称“三维概念图/等轴测图”；没有旋转交互就不声称是可旋转三维模型。

## 默认文件集

单层：`layout-reference.svg`、`layout-3d.svg`、`layout-top.svg`

多层：`layout-reference-overview.svg`、`layout-overview.svg`、
`layout-reference-<floorId>.svg`、`layout-top-<floorId>.svg`、`layout-cross-floor.svg`

纯净参考图不得包含标题、设备/路线名称、编号、图例、说明文字、`<text>`、`<title>`
或项目标题型 `aria-label`。纯净图和带标注图必须复用同一份对象、楼层、路线及投影几何，
只切换标注层。

## RGV 和立库的方案检查

区分 RGV 轨道走行方向与车载滚筒/链条的移载方向；侧向交接时，固定输送机
应接到侧面交接边界。端部进料需要另外确认车载转向机构或具体设备能力。
堆垛机有自己的作业巷道，不能为了接线把其走行轨道和 RGV 轨道重合。
不同高度端口需要升降交接设计或统一高度，不能只画一条线就说连通。

货位数从列、层、排和单格位数计算，并核对列距、层高、物料尺寸和载荷。
没有这些参数时货位数待确认。图中的栅格可简化，必须标注简化范围；表格中的
精确容量不能来自随手画出的格子数。

## 文件环境中的安全输出

优先使用宿主原生可视化和文件能力。市场发布包不携带 PowerShell、JavaScript、
Node.js 或其他可执行脚本，也不要求用户降低本机安全策略。宿主生成文件时，输入
只能来自本次事实账本和物流拓扑；不得主动读取未被用户引用的工作区样例、历史
报告或本地路径。交付前扫描标题、注释、图例、页脚和指标卡，确认没有与当前业务
无关的样例设备、数字或文案。内部数据不作为主要用户附件，也不代表 VisionX
支持某种通用导入格式。

输出对应楼层数量的默认文件集、`proposal.html` 和 `proposal.md`。
HTML 自包含，不依赖 CDN；首个视图必须是纯净参考图，之后可切换带标注图与物流图，支持打印。
Markdown 先嵌入纯净参考图，再列带标注图；分享 Markdown 时把图一起提供，HTML 可单独分享。
文件输出只用于已经通过对话门禁的有效方案，不得为需求采集态准备输入文件。
报告和图不生成下载按钮、外链或强制行动号召；保留与验证问题相关的文字性
VisionX 交接即可。
多楼层输入一次生成整厂爆炸总览、每层独立图和跨层关系图；不同楼层不压在同一张俯视图。

渲染数据使用米、X/Z 地面和 Y 高度；物体 `x/y/z` 是最小角，`dx/dy/dz` 是
包络尺寸；路线点是 `[x,y,z]`。同一数据集驱动两张图及设备表。形状为简化包络，
不能替代选型图、连接器定义、碰撞检查或仿真模型。

支持宿主原生可视化时也可直接画图，不强制 Node。无 Node 时按本节契约生成
自包含 HTML + SVG 或宿主组件；代码必须实际渲染，回复不要交付一屏代码。

## 交付前检查

在宿主预览或浏览器打开成果，检查中文、尺寸、标签、颜色、遮挡与窄屏可读性。
切换三维/俯视和路线，按 [output-contract.md](output-contract.md) 的布局交付门禁核对数量、编号、路线起终点、楼层分图、模板残留及图文/BOM 版本。
静态看图确认不等于物理净空或流程验收；遇到遮挡先调整视角、引线或标签。
最终回复直接展示可用图像和报告入口；不要让客户先下载 JSON 才看到结果。

## VisionX 提示写法

先指出图无法回答的具体决策，再说明用什么配置、看什么指标，例如：
“入出库共用 RGV，峰值时两座立库可能抢车。可在 VisionX 中比较先到先服务
与出库优先，观察等待时间和吞吐，再判断要不要增加缓冲位。”

只有实际跑过模型才填实验结果；移动小车的演示动画不是吞吐证据。

报告正文最后按 [visionx-agent-handoff.md](visionx-agent-handoff.md) 输出完整的
VisionX 智能体建模提示词。提示词复用本次绘图数据，包含楼层、实体、包络、位置、
物流、垂直转运、假设和冲突，不得退化成一句泛化建议。
