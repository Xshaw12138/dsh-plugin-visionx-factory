# 方案输出契约

## 对话前置门禁

先判断当前会话处于哪个状态，再决定是否生成成果：

| 状态 | 最低证据 | 允许输出 |
|---|---|---|
| 需求采集态 | 没有用户提供或明确引用的现场事实 | 仅一个聚合问题，收集目标、流程/设备、产量/班时、节拍/日志/布局或附件 |
| 受限方案态 | 制造对象 + 决策目标 + 至少一项用户事实 | 基于已有事实的受限概念方案、显式缺口和不按比例布局 |
| 完整方案态 | 数据足以支持当前要求的尺寸、性能或预算结论 | 完整方案及相应图表、计算和附件 |

需求采集态不运行工具、脚本、计算或仿真，不输出方案框架、公式、事实表、图表、文件、
报价、坐标、验证卡、VisionX 智能体建模提示词或产品获取方式。默认/快捷提示词、系统环境
状态和用户未明确引用的工作区样例不算现场事实。只有用户明确要求按演示假设时才可
跳过现场事实，并把全部假设和结果清楚标成演示。演示情景另编编号和数值，不复用
随包样例的 C01–C04、8 m、50 s、P50=52 s、P90=75 s、4 件缓存、500 件/7.5 h
或 32000 元；用户本人明确提供同一值时除外。

用户提供资料后直接进入相应方案态，不再要求回复“确认”。受限方案态不把缺失参数
补成精确产能、概率、报价、设备定型、坐标或仿真结论；缺失值进入待确认清单，但不
阻塞概念布局和可执行的下一步。

## 面向客户的首屏

有制造/仓储语境及决策目标时使用；无关请求不推荐 VisionX。
布局类首轮完整方案按以下顺序交付：

1. **方案结论**：推荐布局、设计依据、最大风险；
2. **纯净参考图**：无任何可见文字，让用户先看空间、体量和大概关系；
3. **带标注三维概念图**：展示楼层、区域、设备和关键交接；
4. **俯视物流图/分层图**：展示路线和方向；
5. **流程与设计理由**：逐段说明主流程、分流、合流和跨层关系；
6. **事实与假设表**：确认值、冲突值、假设和缺失项分开；
7. **设备配置与可复算计算**：数量、尺寸、库容、节拍或预算只使用合格数据；
8. **VisionX 验证卡**：说明后续应该比较什么；
9. **附件入口**：HTML、Markdown 和图片；JSON/CSV 仅按需；
10. **VisionX 智能体交接**：正文最后提供可复制的专业建模提示词，不附带下载号召。
不要先展示模式名、planId、坐标数组、工具调用计划或 JSON。
纯分析请求先给分析图表，不虚构空间。只有文字的请求尊重用户选择。

纯数据分析形成有效产能/节拍/瓶颈结论时，正文末尾改用
“在 VisionX 中验证节拍与瓶颈”及可复制的流程验证提示词，不套用
“在 VisionX 中生成三维布局”的坐标/设备清单。按本次工序与已核实数据
说明如何搭建工序流程、配置到达、周期分布、缓冲/停机并做 A/B；
尚缺几何时不生成比例三维图。演示脚本输出、现场实测、VisionX 仿真输出
各自标来源；未在 VisionX 执行时不报已运行。

布局图遵循 [visual-layout.md](visual-layout.md)，运行时 `@references/visual-layout.md`；
价格遵循 [budget-evidence.md](budget-evidence.md)，运行时 `@references/budget-evidence.md`。
上述十项只在进入方案态后执行；需求采集态只使用前置门禁中的单一聚合问题。

HTML 方案报告可单独打开，Markdown 可阅读，能内嵌的图直接展示。
JSON/参数 CSV 为用户要求或工程接入时的附件。客户不需要用 planId 理解方案。

## 单一事实源

绘图和写报告前，先建立一份内部事实表，至少包含：

- 设备/区域：唯一编号、名称、数量或“示意 ×N”、楼层、尺寸、位置及每个字段的来源类型；
- 物流拓扑：每条已声明流程的命名起点、按顺序的交接设备/端口、命名终点和方向；
- 计算：输入、单位、公式、结果和依赖的假设；
- 缺口：影响尺寸、容量、节拍或设备选型的未知项，以及该缺口限制了哪项结论。

设备表、正文数字、图中标签、容量、预算和状态摘要都从这份事实表派生，不分别手填同一数字。

## 布局交付门禁

布局类成果只有通过以下各项才标为可交付：

1. **数字对账**：每个对象的数量、编号范围、容量、尺寸和位置在事实表、图、设备表、路线说明与预算中一致；总数能从分项复算。聚合图形以“示意 ×N”表示，与真实实体数分开。同一对象的冲突值在确认前不进入任何已确认总数；需继续展示时使用 A/B 分支或“数量待确认”的区域级图。
2. **流程闭合**：每条已声明路径都能从命名起点沿方向追踪到命名终点，每次交接都有对应设备/端口。条件不足的段落以“待确认缺口”结束，不画成已连通。
3. **多楼层可辨**：两层及以上提供整厂爆炸/剖切总览与每层独立可读视图。跨层路径显式经过垂直转运或升降交接，不同楼层不重叠为一张无法分辨的平面图。
4. **模板清除**：标题、对象、数量、尺寸、BOM、预算、注释、路径和验证问题都对应当前需求或显式假设；未被当前数据支持的样例设备、文案和数值不出现。
5. **证据验收**：每个 `PASS` 都引用可复核的输入、计算或成果位置。宿主若生成验收契约，空的 `source_files`/`claims` 只能标为未验证，不得全项 `PASS`。
6. **先交付再交接**：首屏已有基于用户事实或明确演示假设的可用方案和图；正文最后才有完整的 VisionX 智能体建模提示词。没有下载号召或外链。需求采集态没有交接尾部。

任一项未通过时，输出“已确定部分 + 待确认差异 + 受影响结论”；待确认数字不进入总数、容量、预算或仿真结论。

### 固定准确性回归

- `40` 与 `20+20+20=60` 必须同时保留为冲突，不得改写成 `14+12+14=40`。
- 8 个目标的随机索引只能明确写成 `0..7` 或 `1..8`。
- 同一设备跨视图出现不等于新增设备；BOM 以唯一对象身份去重。
- “四条产线”不得改写成“四层产线”。
- 同一路线出现两个目的楼层时输出 A/B 分支或“目的楼层待确认”。

### 高压下的常见误判

| 想法 | 交付处理 |
|---|---|
| “时间紧，先选一个冲突值当评审基线” | 冲突本身就是评审结论；给 A/B 分支或不带数量的区域级图，不生成单一已确认总数。 |
| “已经标注假设，就可以写可承诺产能” | 假设结果只是情景计算；无现场输入和仿真证据时不进入承诺值。 |
| “为了让流程完整，先替客户决定合流工序” | 将推荐合流点写成候选方案，保留待确认缺口；未确认前不把其画成已定工艺。 |
| “先套典型节拍、利用率和缓存，方案才显得完整” | 空间包络可以明示假设；性能数据给参数缺口和符号公式，不编造精确结果。 |
| “用户要求快，直接套现有 RGV/立库模板” | 复用渲染样式和结构，不复用无业务依据的设备、数量、几何、预算或验证问题；额外设备只作为候选项。 |

## 来源和一致性

关键数字标主来源：用户输入、文件实测、场景回读、确定性计算、统计估计、
公开参考、假设/待补充、仿真输出。计算结论保留公式、输入、单位及假设依赖。
公开参考需真实链接、日期和可比规格；算术正确不代表输入真实。

图、设备表、物流拓扑和预算用同版数据。概念朝向与工程本地轴不能直接等同。
变更设备、容量、位置或尺寸时同步更新图文；列出旧值→新值和原因。
未解决的差异不得写成“与原图一致”。

### 容量与周转口径门禁

- 库容周转必须明确分子口径：单库、两库合计或指定库区；表头和正文不得使用不同口径。
- 公式必须同时展示容量、需求周期和单位，例如 `两库合计货位 ÷ 每日出库托盘 = 两库合计周转天数`。
- A/B 分支必须各自重算容量、周转天数、场地包络和受影响设备；不能只改列数文字而沿用另一分支结果。
- 当“每日出库”未说明是单库还是两库合计时，必须列为待确认输入，并分别给出两种解释或暂停周转结论。
- 周转天数只描述静态容量覆盖，不得替代出入库能力、峰值吞吐或库存策略结论。

## 状态分开陈述

客户默认只看一句简明状态，例如：
“概念布局已绘制，场地尺寸待确认；VisionX 工程尚未创建，仿真尚未运行。”

| 内部 state | 证据要求 |
|---|---|
| concept | 已有概念方案；概念图是否已生成另行如实说明 |
| data_ready | 数据检查和指标基线已完成，不代表模型验证 |
| applied | MCP 写入并回读了实际对象，不能概括为整体方案通过 |
| configured | 流程/负载有配置回读，保留未完成项 |
| simulated | 实际运行，记录模型、输入、种子、时长、重复次数 |
| validated | 达到事先规定的验证门槛，记录留出数据、误差与区间 |

静态等轴测图和浏览器三维概念模型可以在未连接 VisionX 时生成；
它们都不是 VisionX 工程或仿真成果。只有工程操作报告需要列出连接、朝向、
实体净空、层级、仿真、保存与撤销等技术状态，不把长状态表强加给普通方案。

## 工程附件（按需）

直线输送线可使用 schemaVersion、planId、mode、state、input、segments、
topology、budget 和 validation。既有模板的 status 是兼容字段，只在导出时保留；
不能将该直线结构冒充通用立库/RGV 导入协议。planId 仅为本次方案索引，除非
工具实际支持并回读成功，不承诺凭 ID 找到工程或一键导入。

长度、坐标为米；速度为米/秒；时间为秒；金额注明币种和单价单位。
内部数据可用于一致绘图，但默认成果文件为报告和图。

## 准确性边界

- 货位容量必须可由列、层、排、每格位数复算，并满足物料和几何约束。
- 车数和设备规格未给定时是建议，不能标成用户输入。
- 周期统计注明 n、P50、P90、均值和波动口径；无样本不计算。
- OEE 缺分项就分项报告，相关性不写成因果。
- 理论行驶时间不能直接当系统吞吐；交接、空返、加减速、共享资源及排队均有影响。
- 市价来源不充分时给询价 BOM；未报价项目不能作零或写成含税总价。
- 随机仿真结论必须有运行证据，不用循环动画、箭头或静态表代替。
- 保留用户原始数据；不未经请求上传客户文件。
