# VisionX MCP 路由与安全操作

仅在当前环境确实提供 `mcp__visionx__*` 工具，或用户明确要求连接活动 VisionX
项目时读取。

## 优先高层工具

如果实时工具清单存在以下能力，优先使用：

1. `get_visionx_status`：返回 Bridge、GUI、项目、仿真与契约版本状态。
2. `preview_conveyor_layout`：让平台无关计算核心校验参数并缓存 `planId`。
3. `apply_conveyor_layout`：按 `planId` 原子创建、设参、定位和吸附连接。

不要猜测工具存在，也不要猜 schema。高层工具返回的计划、版本和实际 ID 优先于
本地参考。

## 原子工具回退

高层工具尚未提供时，按实时 MCP 能力回退：

1. `get_scene_status`：确认活动场景与修改状态。
2. `list_equipments`：解析现有对象与 ID。
3. `list_equipment_types`：解析可创建滚筒输送线类型。
4. `list_object_properties`：解析尺寸、速度与可编辑范围。
5. `get_equipment_info`：读取层级、变换与复合信息。
6. `list_connector_infos`：记录相邻端点与 peers。

回退模式不能声称支持高层工具的原子批量撤销。若无法证明失败不会留下半成品，
应先说明限制，并分成可验证的小批次。

## 写入计划与授权边界

- 只有“把方案创建/应用/落地到当前 VisionX 场景”这类明确请求才授权场景写入；
  数据分析或概念预览本身不授权写入。
- 写入前核对 `planId`、段数、类型、长度、宽、高、速度、命名、位置、方向、
  相邻拓扑和预期自由端点。
- Bridge 与 GUI 契约不兼容时只报告版本差异，不执行场景修改。
- 不修改 Flow，不配置 LoadCreator，不启动长时间仿真。

## 执行与验收

- 有依赖的创建、定位与连接保持顺序；只并行执行互不依赖且不重叠的操作。
- 每批写入后回读所有受影响对象的实际 ID、属性、层级、位置、旋转与连接器。
- `peerIds` 只证明拓扑，不证明净空。检查每段与相邻设备的实体包络；只允许目标
  端面零面积接触。
- 分别核对轨道走行方向、移载方向和端口高度；逻辑连接成功不代表物料能交接。
  不将堆垛机巷道移到 RGV 轨道，不为触发吸附而把输送机重叠进轨道区域。
  设备原点、默认朝向和复合子对象范围必须回读，不能只比较根对象坐标。
- 当前回读与概念图不一致时列差异；更改设备配置、货位数、尺寸或口位需先说明
  替代方案，随后同步图、表和预算。不得把改后的范围写成原方案已通过。
- 验收必须分别报告：
  - `connectivity verified`；
  - `clearance verified`；
  - `orientation verified`；
  - `ownership verified`。
- 验收未通过时停止，说明实际值、期望值和修正建议。

## 撤销与保存

- 高层 apply 工具应把整条布局作为一次可见的 BatchEdit；只有工具明确返回成功时
  才报告“可一次 Undo”。
- 默认不保存，让用户先看到和检查布局。
- 只有用户明确要求保存且验收通过时才调用保存；保存后确认 `isModified=false`。
- 保存、连接、净空分别报告实际状态，不使用无条件“已验证”的总结。
  `canUndo=true` 不证明一次撤销涵盖整个方案；没有批次证据就不承诺整体 Undo。

## 已知兼容性注意

若当前 MCP 仍出现以下行为，使用对应规避；若实时版本已修复，以实时行为为准。

- `create_equipment` 传 `name` 可能解析失败：先创建，再 `rename_object`。
- 创建位置可能被自动吸附覆盖：创建后读取实际位置，再决定是否纠正。
- Length/Width/Height 的单位标签可能误写为 mm，但实际使用米：用已知对象或
  高层参数契约核验，不盲目换算。
- `set_object_property` 可能报错但值已生效：先回读，再决定是否重试。
- 原子 `connect_connectors` 可能拒绝可吸附输送设备：优先使用高层
  `apply_conveyor_layout` 复用 GUI 吸附；没有高层工具时用几何对齐并验证。

任何时候都不要通过直接编辑 VisionX 项目文件或执行本地脚本来冒充场景写入。
